## 一、先定义目标：到底要建设什么机构能力

“价值型资管”和“对冲基金”不是同一种 operating model。杠杆、做空、衍生品、流动性、交易频率和合规要求都会改变能力优先级。因此，在任何工具开发之前，必须先确认投资授权（mandate）。

### 1.1 建议采用的默认工作假设

以下是为了推进建设而设定的默认口径，不是不可修改的结论：

| 项目 | 默认口径 | 待确认事项 |
|---|---|---|
| 投资风格 | 基本面驱动、长期、价值偏成长、长仓为主 | 是否允许量化择时或主题轮动 |
| 投资范围 | A 股、港股、美股上市权益 | 是否包含一级市场、债券、商品、加密资产 |
| 投资期限 | 3–5 年为主 | 是否保留短期事件驱动策略 |
| 基准 | 按市场/策略指定可投资的总回报基准 | 组合使用单一基准还是混合基准 |
| 组合目标 | 追求长期复合回报，同时控制永久损失 | 最大可接受回撤、现金区间和集中度上限 |
| 杠杆与做空 | 默认不使用 | 若启用，需新增保证金、借券、流动性和交易对手能力 |
| 服务对象 | 首期作为自有资金的投研与决策支持系统 | 若管理第三方资金，必须启动 P3 机构运营与属地合规 |
| 最终决策 | AI 提供证据、情景与建议，人类审批 | 哪些动作必须二次复核或投资委员会批准 |

### 1.2 分成两种目标状态

**目标 A：机构级投资决策系统（当前建设重点）**

- 从机会发现到研究、估值、决策、组合、监控和复盘形成闭环。
- 数据有时点、来源、版本和质量记录。
- 结论可复现，工具有测试，关键决策有人审和留痕。
- 能回答“为什么买、买多少、何时重审、结果从哪里来”。

**目标 B：真实资管机构 operating system（条件性目标）**

- 面向第三方客户资金。
- 增加订单管理、经纪商与托管、成交分配、清算对账、基金会计、NAV、监管和客户报告等能力。
- 具体建设内容由注册地、产品结构、客户类型和监管身份决定。

在目标 A 尚未跑通前，不应把大量资源投入目标 B；但如果开始管理第三方资金，目标 B 的合规和运营能力必须立即前置，不能仍按普通 P2/P3 待办处理。

## 二、机构投资不是 14 个串行环节，而是一条主流程加五条控制线

### 2.1 投资主流程

```text
投资授权 → 机会发现 → 研究与预测 → 估值与决策 → 组合构建
        → 交易执行 → 持续监控 → 业绩归因与决策复盘 → 规则迭代
```

### 2.2 贯穿全流程的控制线

```text
数据治理｜风险管理｜合规与信息边界｜模型治理与测试｜审计留痕与知识管理
```

风险、数据和合规不是研究完成后的附加步骤，而是从数据获取、研究引用、仓位建议到绩效展示都必须遵守的横向约束。

### 2.3 两类能力必须分开管理

| 类别 | 解决的问题 | 典型能力 |
|---|---|---|
| 机构底座 | 能不能稳定、正确、可追责地管理投资决策 | IPS、账本、数据、估值、风险、归因、合规、测试、监控 |
| Alpha 模块 | 在既定投资授权内，靠什么获得超额收益 | 行业漏斗、新兴赢家、瓶颈套利、因子、宏观、事件驱动、渠道验证 |

机构底座具有普适性；宏观轮动、十倍股、特殊机会等属于策略选择，不应被表述为所有价值机构都必须拥有的核心能力。

## 三、用成熟度而不是“强/弱”评价现状

### 3.1 成熟度定义

| 等级 | 定义 | 判断标准 |
|---|---|---|
| L0 | 不存在 | 没有明确流程或资产 |
| L1 | 人工/文档化 | 有原则、模板或零散报告，依赖人工执行 |
| L2 | 可重复 | 有 skill 或工具，可按相似步骤重复运行 |
| L3 | 结构化 | 有明确输入输出、结构化数据和交叉验证 |
| L4 | 生产化 | 自动化、测试、监控、异常处理、权限和版本齐全 |
| L5 | 可审计 | 可完整重放历史结果，并经独立验证或审计 |

> “存在一个 skill”不等于机构能力已经建成；“出过一份报告”也不等于拥有稳定的数据管线。

### 3.2 当前能力盘点

| # | 能力域 | 当前 | 现有证据 | 关键缺口 | 目标 |
|---|---|:---:|---|---|:---:|
| 1 | 投资授权与治理 | L1 | 投资哲学、大师镜片、checklist | 无正式 IPS、基准、风险预算、禁投与审批规则 | L4 |
| 2 | 机会发现 | L2 | industry-funnel、quality-screen、bottleneck-hunter、stock_screener、多个召回池 | 原型分散，缺统一标的库、全市场点时扫描、去重与效果评估 | L4 |
| 3 | 尽调研究 | L3 | investment-research/team、earnings、management、private-company、deep-company | 缺标准样本集、输出回归测试、预测校准和外部质量基准 | L4 |
| 4 | 估值建模 | L2 | financial_rigor 三情景、报告内反向 DCF、Morningstar 公允价值 | 无统一 DCF/SOTP 工具、行业模板、假设版本和模型验证 | L4 |
| 5 | 决策与仓位 | L2 | checklist、master-lens、非对称赔率与定性仓位建议 | 无结构化决策日志；凯利输入未经校准；未接组合风险预算 | L4 |
| 6 | 组合构建 | L2 | portfolio-review 的集中度、机会成本和定性压力测试 | 无统一持仓账本、量化暴露、流动性和约束优化 | L4 |
| 7 | 风险管理 | L1 | 塔勒布生存测试、定性情景 | 无组合级波动/回撤/beta/因子/货币/流动性和数值压力测试 | L4 |
| 8 | 交易执行 | L1 | 手工操作记录 | 无订单状态、成交成本、预交易约束和执行质量评价 | L3；真实资管为 L4 |
| 9 | 监控与跟踪 | L2 | thesis-tracker、thesis-drift、news-pulse、瓶颈 watchlist | 缺统一调度、财报/催化剂日历、告警去重和服务可靠性 | L4 |
| 10 | 业绩与归因 | L0–L1 | 零散盈亏和复盘记录 | 无现金流口径、基准、TWR/MWR、费用汇率及系统归因 | L4 |
| 11 | 宏观与配置 | L1 | macro-analyst、宏观利率专题 | 无与 mandate 绑定的 regime、跨资产配置和再平衡框架 | L3（按策略需要） |
| 12 | 数据基础设施 | L2 | financial-data、ashare_data、xueqiu、Morningstar、局部 CSV/JSON | 无 security master、point-in-time 基本面、统一行情/公司行动/汇率/基准层 | L4 |
| 13 | 合规与模型治理 | L1 | 报告免责声明、report_audit、部分数据规范 | 无数据授权清单、MNPI 边界、模型登记、审批、权限、异常与回滚机制 | L4 |
| 14 | 知识管理 | L1–L2 | reports、memory、data/watchlist.json、bottleneck watchlist | 多套 watchlist 分散，无统一状态机、论文版本、决策与错误知识库 | L4 |
| 15 | 资管运营 | L0 | 不在当前项目核心范围 | OMS/EMS、托管、清算、对账、NAV、客户与监管报告 | 条件性建设 |

### 3.3 对现状的准确表述

AI Berkshire 当前最成熟的是**结构化公司研究工作流**，但尚未经过足够的基准测试、长期预测校准和独立审计，因此不宜直接使用“世界级”或“业内领先”作为能力结论。

机会发现也不是“完全空白”。仓库已有：

- `industry-funnel`：从行业全市场逐层筛选到少数候选。
- `stock_screener.py` 与 `data/watchlist.json`：动量发现和基本面验证原型。
- `bottleneck-hunter`：持续维护的瓶颈地图与观察名单。
- A/H/美股召回池、科创板召回池、净现金折价股全市场扫描等研究产物。

准确的缺口是：**已有多个分散原型和一次性产物，但尚未形成统一、点时、全市场、可评估、可稳定调度的生产级机会发现管线。**

## 四、P0：先补机构底座，建立最小可用闭环

P0 的目标不是增加最多的 skill，而是让任何一次投资决策都能被记录、复现、监控和复盘。

### P0-1：投资授权与 IPS

- [ ] 新建 `docs/INVESTMENT-MANDATE.md`
- [ ] 新建机器可读的 `config/investment-policy.yaml`
- [ ] 明确投资范围、基准、风险预算、仓位和集中度上限、流动性下限、禁投清单、杠杆/衍生品权限、审批规则和复审频率

**完成定义：**

- 所有仓位、组合风险、卖出和再平衡建议都引用同一套约束。
- 不再在 skill 中硬编码“前十大/前三大/现金比例”等通用阈值。
- 基准必须能反映投资 mandate，并使用可投资的总回报口径。

影响：★★★★★　工作量：小–中　依赖：无

### P0-2：统一标的主数据、交易账本与组合主账

- [ ] 建立 security master：内部 ID、各市场代码、交易所、币种、行业、上市/退市状态
- [ ] 建立 transaction ledger：买卖、股息、费用、税费、申赎、换汇、拆股和其他公司行动
- [ ] 从交易记录重建每日现金、持仓、成本与组合净值
- [ ] 建立 benchmark、FX 和 corporate action 的统一接口

**完成定义：**

- 给定任意历史日期，可以重建当日持仓、现金和组合净值。
- 账本结果与人工样例完全一致；差异能定位到具体交易或公司行动。
- 风险、业绩、归因、告警和税务功能只读取这一个事实源。

影响：★★★★★　工作量：大　依赖：P0-1

### P0-3：统一数据层 v1

- [ ] A/H/美股统一行情、复权总回报、财务报表、估值、FX、基准和公司行动
- [ ] 所有记录包含 `as_of`、`available_at`、来源、抓取时间、币种、单位和版本
- [ ] 建立 point-in-time 基本面，避免回测使用当时尚未公布的数据
- [ ] 建立数据新鲜度、完整性、跨源差异、缺失和异常值检查
- [ ] 记录数据供应商许可、抓取限制和可再分发边界

**完成定义：**

- 同一输入快照可重复产生相同输出。
- 缺失、过期、冲突数据不会被静默使用。
- 核心指标保留原始来源和标准化后的值，可追溯转换过程。

影响：★★★★★　工作量：大　依赖：P0-2 的数据模型

### P0-4：测试、数据治理与模型治理

- [ ] 核心工具增加单元测试、边界测试和 golden fixtures
- [ ] skill 增加固定样本的输出回归测试和关键字段检查
- [ ] 建立模型登记：版本、用途、输入、限制、审批人、最近验证日期
- [ ] 建立数据/模型异常处理、回滚和人工接管流程
- [ ] 修复 `financial_rigor.py exact_calc` 先按浮点数计算后再转 Decimal 的问题

**完成定义：**

- `0.1 + 0.2` 等精确运算测试通过，不再输出伪精确结果。
- 任一工具升级都能识别是否破坏历史样例。
- 仓位、买卖和风险建议必须显示模型版本、关键假设与人工审批状态。

影响：★★★★★　工作量：中　依赖：与 P0-2/P0-3 并行

### P0-5：组合风险与业绩计算 MVP

- [ ] `tools/portfolio_risk.py`：波动、最大回撤、beta、HHI、行业/地域/货币暴露、相关性和历史压力情景
- [ ] `tools/performance.py`：TWR、MWR、总回报、基准超额、费用前后收益和多币种换算
- [ ] 首批压力测试覆盖市场下跌、利率、汇率、行业冲击和单一持仓归零

**完成定义：**

- 组合和基准使用一致的时间区间、频率、币种和总回报口径。
- 结果能与人工计算样例及第二实现交叉验证。
- VaR 只作为补充指标，不替代回撤、流动性、集中度和尾部情景。

影响：★★★★★　工作量：中–大　依赖：P0-1/P0-2/P0-3

## 五、P1：跑通“研究—决策—组合—监控—复盘”

### P1-1：结构化决策日志与投资委员会记录

- [ ] `/decision-journal`
- [ ] 每次决策记录：论文版本、价格、估值区间、概率与情景、关键证伪条件、建议仓位、替代机会、审批和下次复审日期
- [ ] 区分“信息判断正确但结果不利”和“推理或执行错误”

**完成定义：**历史时点只能看到当时已知信息；后续结果不得回填改写原始判断。

### P1-2：估值模型框架，而不只是一个 DCF 公式

- [ ] `tools/dcf.py`：多阶段 DCF、反向 DCF、终值和 WACC 敏感性
- [ ] SOTP：分部、投资资产、净现金/负债、少数股东和重复加计检查
- [ ] 行业模板：金融、资源、周期、SaaS/平台、消费、未盈利成长股
- [ ] 每个假设记录来源、日期、版本和对估值的敏感度

**完成定义：**同一输入可复现；单位、币种和股本口径有测试；终值占比过高时自动警示；至少与一种独立估值方法交叉验证。

### P1-3：完整风险与压力测试

- [ ] 补充因子、风格、流动性、容量、拥挤度、杠杆和交易对手暴露
- [ ] 支持历史情景、假设情景和反向压力测试
- [ ] 风险限额来自 IPS，越限生成解释和审批记录

### P1-4：业绩归因与决策校准

- [ ] `/performance-attribution`
- [ ] 明确采用 Brinson、因子或交易级归因的适用场景
- [ ] 区分配置、选股、择时、汇率、费用和交互影响
- [ ] 统计概率预测的 Brier score、估值区间覆盖率和论文红线命中情况
- [ ] 形成可检索的错误模式库，而非简单“错题集”

> 业绩归因依赖交易账本、现金流、基准、费用、FX 和公司行动，实际工作量应按“大”估计，而不是单独开发一个中等规模 skill。

### P1-5：统一 Watchlist、论文库与自动监控

- [ ] 合并 `data/watchlist.json`、瓶颈 watchlist、召回池和持仓跟踪入口
- [ ] 状态机：发现 → 初筛 → 深研 → 候选 → 持有 → 退出 → 归档
- [ ] 每个标的有负责人、论文版本、下一催化剂、红线和复审日期
- [ ] 自动维护财报、分红、监管、催化剂和论文 KPI 日历
- [ ] 告警具备去重、优先级、重试、静默期和数据过期提示

### P1-6：仓位与卖出纪律

- [ ] `tools/position_sizing.py`：分数凯利只作为参考，并加入 IPS 上限、流动性、相关性、组合风险预算和概率置信区间
- [ ] `/sell-discipline`：论文证伪、估值透支、机会成本、风险越限、税务和流动性规则
- [ ] 禁止仅凭“高赔率”或单一评分直接生成固定仓位

卖出纪律属于决策与风险闭环，不单独归类为 Alpha 来源。

### P1-7：会计异常与治理筛查

- [ ] `/forensic-accounting`
- [ ] 覆盖应收、存货、现金流与利润背离、资本化、关联交易、商誉、审计意见和股权质押
- [ ] Benford、Beneish M-Score 仅标记异常线索，不输出“证明造假”的结论
- [ ] `/governance-screen` 统一处理股权结构、AB 股、薪酬对齐、减持和利益冲突

## 六、P2：Alpha 实验室——在底座之上扩展策略

Alpha 模块必须明确策略假设、适用市场、风险预算和退出条件，并通过点时、样本外和含成本验证，不能只靠事后案例证明有效。

### P2-1：新兴赢家发现引擎 `/emerging-winners`

用“新兴赢家”替代“十倍股猎手”，避免以结果标签驱动研究。

**候选维度：**

1. 市值与流动性允许较长成长空间，但不把小市值本身当作优势。
2. TAM、渗透率和产业生命周期处于有利阶段。
3. 单位经济成立，增长可复制且有再投资空间。
4. 收入、毛利、现金流和资本效率能够相互验证。
5. 创始人/管理层资本配置有可核实记录。
6. 存在被市场忽略的业务期权或认知差。
7. 有明确竞争壁垒，而不只是热门主题。
8. 估值允许失败，避免靠永久高估值实现“戴维斯双击”。

**组合方法：**

- 只作为有明确风险预算的卫星策略。
- 先定义最大总仓位、单一仓位、流动性和最大损失，再选择候选。
- 目标是提高组合期望收益，不以“找到多少只十倍股”作为 KPI。

**验证要求：**

- 使用当时可得的股票池和财务数据。
- 纳入退市、失败样本和交易成本。
- 报告候选命中率、假阳性、最大回撤、资金容量和样本外表现。

### P2-2：多因子与系统化筛选 `/factor-screen`

- [ ] 价值、质量、成长、动量、低波、规模和盈利修正因子
- [ ] 行业/市场中性化和因子相关性分析
- [ ] 点时成分股、退市收益、再平衡、换手、滑点和税费
- [ ] 训练期、验证期、样本外期严格分离
- [ ] 将因子用于缩小研究范围，而非黑箱自动下单

### P2-3：宏观 regime 与资产配置（策略可选）

- [ ] `/macro-regime`：增长、通胀、流动性、信用、利率、汇率和政策周期
- [ ] `/asset-allocation`：目标区间、再平衡触发、风险预算和基准
- [ ] 明确宏观判断只影响哪些决策，避免在自下而上研究中随意改变估值假设

### P2-4：行业景气、轮动与主题（策略可选）

- [ ] `/sector-rotation`：订单、价格、产能、库存、盈利修正、资金流和相对强弱
- [ ] `/thematic`：主题定义、产业链受益纯度、拥挤度、估值和退出条件
- [ ] 与 `industry-research`、`industry-funnel` 共享行业分类和候选主数据

### P2-5：事件驱动与特殊机会

- [ ] `/special-situations`：并购、分拆、私有化、要约、回购、重组、指数调整和融资事件
- [ ] 每类事件单独建模成交概率、时间价值、法律条件、融资风险和下行情景
- [ ] 不使用“确定性较高”概括整个类别；特殊机会只是收益驱动与市场 beta 可能不同

### P2-6：一手验证与信息 Edge

- [ ] `/scuttlebutt`、`/channel-check`、管理层/IR 问题库
- [ ] 访谈客户、供应商、渠道和行业专家前，先通过 MNPI、保密、隐私、利益冲突和记录政策检查
- [ ] 区分可验证事实、受访者观点和研究员推断
- [ ] 另类数据记录授权、代表性、更新频率和失效风险

### P2-7：分市场与另类资产模块

- [ ] A 股：制度、涨跌停、北交所、可转债条款、股权质押和公司治理
- [ ] 港股：流动性、配售、老千股特征、AH 溢价和港股通资金
- [ ] 美股：做空、期权、回购、13F、SPAC 和证券诉讼
- [ ] 一级市场/REITs/债券/商品/加密资产分别建立 mandate 后再开发

“可转债下有保底”“小盘更容易十倍”等只能作为待验证假设，必须同时评估信用、赎回、稀释、流动性和极端损失。

## 七、P3：真实管理第三方资金时才启动的机构运营能力

如果 AI Berkshire 仍是个人或内部投研系统，本节可以暂缓；如果开始管理客户或基金资产，本节立即升为 P0。

- [ ] OMS/EMS：订单、审批、分配、撤单、成交和异常状态
- [ ] 预交易/交易后合规：禁投、集中度、关联交易、最佳执行和个人交易
- [ ] 经纪商、托管人、交易对手、保证金和借券管理
- [ ] 现金、公司行动、清算、持仓与交易对账
- [ ] 基金会计、估值政策、费用计提和 NAV
- [ ] 流动性、申赎、容量和压力下的变现计划
- [ ] 客户报告、监管报送、绩效展示和错误更正政策
- [ ] 权限、密钥、网络安全、灾备、业务连续性和供应商风险
- [ ] 利益冲突、礼品招待、专家网络、MNPI 和举报机制

合规要求必须根据实际司法辖区单独制定。[CFA Asset Manager Code](https://www.cfainstitute.org/insights/professional-learning/refresher-readings/2026/asset-manager-code-of-professional-conduct) 和 [GIPS Standards](https://www.gipsstandards.org/standards/gips-standards-for-firms/) 可作为职业操守、风险、记录与绩效呈现的参考框架，但不能替代属地法律意见或注册要求。

## 八、依赖关系与建议落地顺序

### 8.1 核心依赖图

```text
投资授权/IPS
    ↓
标的主数据 + 交易/现金账本
    ↓
点时数据层 + 数据质量
    ↓
业绩基线 ─→ 组合风险 ─→ 压力测试
    │              │
    └→ 决策日志 ─→ 归因/校准 ─→ 规则迭代
                   │
统一 Watchlist/监控 ┘

测试、模型治理、合规与审计留痕贯穿全部阶段
```

### 8.2 建议里程碑

| 里程碑 | 目标 | 核心交付 | 退出条件 |
|---|---|---|---|
| M0：定规则 | 明确系统服务什么投资策略 | IPS、基准、风险预算、审批与数据边界 | 任一建议能判断是否符合 mandate |
| M1：建事实源 | 历史投资可完整重建 | security master、交易/现金账本、点时数据 v1 | 任意日期持仓与净值可重放 |
| M2：闭环 MVP | 能衡量风险与结果 | 业绩、风险、决策日志、论文版本 | 一笔投资可从决策追踪到结果 |
| M3：可持续运行 | 能自动监控和复盘 | 统一 watchlist、日历、告警、归因、校准 | 告警和复盘有稳定运行记录 |
| M4：扩展 Alpha | 系统发现并验证新机会 | emerging-winners、factor、macro/sector 等 | 通过样本外与含成本验证 |
| M5：真实资管运营 | 支持第三方客户资产 | 交易、托管、NAV、合规和客户报告 | 按属地要求完成独立评估 |

### 8.3 对原优先级的主要调整

| 原安排 | 优化后 |
|---|---|
| position sizing 最先开发 | 先建立 IPS、账本、数据和风险预算，再做仓位工具 |
| 数据基建排在 Alpha 路线第五 | 数据、标的主数据和账本统一前置到 P0 |
| 合规/IPS 为低影响 P2 | 对机构级系统提升为 P0 横向控制线 |
| 业绩归因工作量“中” | 因依赖账本、现金流、费用、基准和 FX，调整为“大” |
| 十倍股猎手为最高核心 Alpha | 改为带独立风险预算的新兴赢家卫星策略 |
| 卖出纪律归为 Alpha | 归入决策、风险和机会成本闭环 |
| 执行/TCA 工作量“小” | 个人模式可简化；真实资管模式属于大型运营工程 |

## 九、所有建设项共用的 Definition of Done

一个 skill 或工具只有同时满足以下条件，才算“机构能力已落地”：

- [ ] **范围明确**：解决什么问题、不解决什么问题、适用什么 mandate。
- [ ] **输入明确**：字段、单位、币种、时点、来源和缺失值规则。
- [ ] **输出明确**：结论、置信度、假设、限制和人工审批点。
- [ ] **可复现**：同一数据快照、配置和版本产生相同结果。
- [ ] **可测试**：正常、边界、异常和历史 golden case 均有自动测试。
- [ ] **防偏差**：回测处理 point-in-time、幸存者偏差、前视偏差、成本和退市样本。
- [ ] **可追溯**：能从最终结论回到来源、转换、模型版本和决策人。
- [ ] **会失败**：数据不足时停止或降级，不制造精确幻觉。
- [ ] **可监控**：记录成功率、耗时、数据新鲜度、异常和人工覆盖率。
- [ ] **可复盘**：上线前定义效果指标，上线后定期校准和淘汰无效规则。

## 十、机构能力建设 KPI

| 维度 | 建议指标 | 目的 |
|---|---|---|
| 数据 | 完整率、新鲜度、跨源差异、可追溯率、账本对账差异 | 证明输入可信 |
| 工具 | 测试覆盖、回归通过率、异常处理率、结果可复现率 | 证明计算可靠 |
| 研究 | 一手来源占比、关键事实双源率、预测留痕率、论文更新及时率 | 证明研究过程扎实 |
| 决策 | 决策日志完整率、审批覆盖率、概率校准、红线命中率 | 证明判断可学习 |
| 组合 | 相对基准回报、最大回撤、风险预算利用率、流动性和集中度 | 证明组合目标一致 |
| 监控 | 告警精确率、重复率、延迟、漏报复盘、过期数据拦截率 | 证明系统能持续运行 |
| Alpha | 样本外收益、命中率、最大回撤、换手与含成本收益、资金容量 | 证明策略不是事后故事 |

KPI 的作用是评价能力建设是否有效，而不是鼓励为了分数牺牲长期投资原则。

## 十一、最终判断

AI Berkshire 已经形成了一套覆盖面较广、可重复运行的公司研究工作流，也已有行业漏斗、瓶颈发现、动量筛选和召回池等机会发现原型。它目前最需要的不是继续横向增加更多“大师”和主题 skill，而是完成三次升级：

1. **从报告升级为记录系统**：有统一标的、交易、持仓、论文和决策事实源。
2. **从能运行升级为可信赖**：有点时数据、测试、模型治理、异常处理和审计留痕。
3. **从研究个股升级为管理闭环**：能计算组合风险与业绩，能监控论文，能归因和校准决策。

完成这些底座后，“新兴赢家发现”“宏观 regime”“板块轮动”“特殊机会”等 Alpha 模块才有可靠的输入、风险边界和评价标准。

> 一句话总结：下一阶段的关键，不是让 AI Berkshire **会分析更多东西**，而是让它对每一个数据、判断、仓位和结果都能回答——**依据是什么、当时知道什么、承担多少风险、最终哪里做对或做错。**
