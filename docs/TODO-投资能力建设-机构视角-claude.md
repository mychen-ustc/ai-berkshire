# TODO：投资能力建设路线图（专业机构视角 · Claude 版）

> 目的：把 AI Berkshire 从"个人研究工具箱"升级为一套**可复现、可审计、可持续改进的机构级投资决策系统**。
> 日期：2026-07-10
> 一句话原则：下一阶段的关键不是"能分析更多东西"，而是让每一个数据、判断、仓位、结果都能回答——**依据是什么、当时知道什么、承担多少风险、最终哪里对了/错了。**

---

## 零、读这份文档的三条前提

1. **能力 ≠ 有一个 skill。** 出过一份报告不等于有稳定数据管线；跑得通一次不等于可复现、可监控、可审计。用成熟度 L0–L5 度量（第三节），不用"强/弱"。
2. **底座普适，Alpha 是选择。** 组合账本、风险、归因、合规是任何机构的"底座"；十倍股、宏观轮动、特殊机会是"策略选择"，取决于投资授权，不是人人必备的核心。
3. **先能不亏钱地运转，再谈赚大钱。** 没有事实源和风险闭环，任何 Alpha 都无法被信任、被评价、被复用。

## 一、第一步永远是定义投资授权（Mandate / IPS）

**写任何工具之前，先确认"这套系统为什么样的投资服务"。** "价值型资管"和"对冲基金"不是同一种 operating model——杠杆、做空、衍生品、流动性、换手率、合规要求完全不同，会直接改变能力优先级。

### 1.1 默认工作假设（可改，但必须先写下来）

| 项目 | 默认口径 | 待确认 |
|---|---|---|
| 投资风格 | 基本面驱动、长期、价值偏成长、长仓为主 | 是否允许量化择时/主题轮动 |
| 投资范围 | A 股、港股、美股上市权益 | 是否含一级市场、债、商品、加密 |
| 投资期限 | 3–5 年为主 | 是否保留短期事件驱动 |
| 基准 | 按市场指定**可投资的总回报**基准（非价格指数） | 单一还是混合基准 |
| 组合目标 | 长期复合回报 + 控制永久损失 | 最大可接受回撤、现金区间、集中度上限 |
| 杠杆/做空 | 默认不用 | 若启用需新增保证金/借券/流动性/对手方能力 |
| 服务对象 | 首期为自有资金的投研与决策支持系统 | 若管第三方资金，立即前置 P3 运营与属地合规 |
| 最终决策 | AI 给证据/情景/建议，**人类审批** | 哪些动作需二次复核或投委会批准 |

### 1.2 两种目标状态，分开管理

- **目标 A（当前重点）：机构级投资决策系统**——从机会发现到复盘形成闭环，数据有时点/来源/版本，结论可复现，关键决策有人审有留痕。
- **目标 B（条件性）：真实资管 operating system**——面向第三方资金，增加 OMS/托管/NAV/清算/监管报告。**目标 A 没跑通前不投入 B；一旦管客户钱，B 的合规运营立即升为 P0。**

## 二、能力地图：一条主流程 + 五条控制线

机构投资不是 14 个串行环节，而是**一条主流程**外加**贯穿始终的横向控制线**——风险、数据、合规不是"研究完再加"的步骤。

**主流程：**
```
投资授权 → 机会发现 → 研究与预测 → 估值与决策 → 组合构建
        → 交易执行 → 持续监控 → 业绩归因与决策复盘 → 规则迭代
```

**控制线（贯穿全程）：** 数据治理 ｜ 风险管理 ｜ 合规与信息边界 ｜ 模型治理与测试 ｜ 审计留痕与知识管理 ｜ **AI 治理**（本系统特有，见第七节）

### 底座 vs Alpha

| 类别 | 解决什么 | 典型能力 |
|---|---|---|
| **机构底座**（普适） | 能否稳定、正确、可追责地管理投资决策 | IPS、账本、数据、估值、风险、归因、合规、测试、监控 |
| **Alpha 模块**（策略选择） | 在既定授权内靠什么获取超额收益 | 行业漏斗、新兴赢家、因子、宏观、事件驱动、渠道验证 |

## 三、成熟度盘点（L0–L5）

| 等级 | 定义 |
|---|---|
| L0 | 不存在 |
| L1 | 人工/文档化（有原则/模板/零散报告，靠人工执行） |
| L2 | 可重复（有 skill/工具，可按相似步骤重复运行） |
| L3 | 结构化（明确输入输出、结构化数据、交叉验证） |
| L4 | 生产化（自动化、测试、监控、异常处理、权限、版本） |
| L5 | 可审计（可完整重放历史结果，经独立验证/审计） |

| # | 能力域 | 当前 | 现有证据 | 关键缺口 | 目标 |
|---|---|:---:|---|---|:---:|
| 1 | 投资授权与治理 | L1 | 投资哲学、13 大师镜片、checklist | 无正式 IPS/基准/风险预算/禁投/审批 | L4 |
| 2 | 机会发现 | L2 | industry-funnel、quality-screen、bottleneck-hunter、stock_screener、多召回池 | 原型分散，无统一标的库、全市场点时扫描、去重与效果评估 | L4 |
| 3 | 尽调研究 | L3 | investment-research/team、earnings、management、private-company、deep-company、master-lens | 无标准样本集、输出回归测试、预测校准、外部质量基准 | L4 |
| 4 | 估值建模 | L2 | financial_rigor 三情景、报告内反向 DCF、Morningstar 公允值 | 无统一 DCF/SOTP 工具、行业模板、假设版本、模型验证 | L4 |
| 5 | 决策与仓位 | L2 | checklist、master-lens、非对称赔率+定性仓位 | 无结构化决策日志；凯利输入未校准；未接风险预算 | L4 |
| 6 | 组合构建 | L2 | portfolio-review 的集中度/机会成本/定性压力 | 无持仓账本、量化暴露、流动性、约束优化 | L4 |
| 7 | 风险管理 | L1 | 塔勒布生存测试、定性情景 | 无组合级波动/回撤/beta/因子/货币/流动性/数值压力 | L4 |
| 8 | 交易执行 | L1 | 手工操作记录 | 无订单状态、成交成本、预交易约束、执行质量 | L3（真实资管 L4） |
| 9 | 监控与跟踪 | L2 | thesis-tracker、thesis-drift、news-pulse、瓶颈 watchlist | 无统一调度、财报/催化剂日历、告警去重、可靠性 | L4 |
| 10 | 业绩与归因 | L0–L1 | 零散盈亏与复盘 | 无现金流口径、基准、TWR/MWR、费用汇率、系统归因 | L4 |
| 11 | 宏观与配置 | L1 | macro-analyst、宏观利率专题 | 无与 mandate 绑定的 regime、跨资产配置、再平衡 | L3（按策略） |
| 12 | 数据基础设施 | L2 | financial-data、ashare_data、xueqiu、Morningstar、局部 CSV/JSON | 无 security master、point-in-time 基本面、统一行情/公司行动/汇率/基准层 | L4 |
| 13 | 合规与模型治理 | L1 | 免责声明、report_audit、部分数据规范 | 无数据授权清单、MNPI 边界、模型登记、审批、权限、回滚 | L4 |
| 14 | 知识管理 | L1–L2 | reports、memory、watchlist.json、瓶颈 watchlist | 多套 watchlist 分散，无统一状态机、论文版本、决策/错误知识库 | L4 |
| 15 | **AI 系统治理**（本系统特有） | L1 | 联网预检、report_audit 准出、financial_rigor、"联网失败禁止伪装"、客观原则 | 无幻觉/漂移/复现的成体系治理（第七节） | L4 |
| 16 | 资管运营 | L0 | 不在当前核心范围 | OMS/EMS、托管、清算、NAV、客户/监管报告 | 条件性 |

### 对现状的准确表述（不吹不贬）

- 最成熟的是**结构化公司研究工作流**（L3）；但**尚未经过基准测试、长期预测校准和独立审计，不宜自称"世界级/业内领先"。**
- 机会发现**不是"完全空白"**：已有 industry-funnel、stock_screener.py + watchlist.json、bottleneck-hunter、A/H/美/科创召回池、净现金折价全市场扫描等。**准确缺口是：多个分散原型和一次性产物，尚未形成统一、点时、全市场、可评估、可稳定调度的生产级机会发现管线。**

## 四、P0 —— 先补机构底座，建立最小可用闭环

目标不是增加最多 skill，而是让**任何一次投资决策都能被记录、复现、监控、复盘**。

### P0-1 投资授权与 IPS　`docs/INVESTMENT-MANDATE.md` + `config/investment-policy.yaml`
- 明确投资范围、基准、风险预算、仓位/集中度上限、流动性下限、禁投清单、杠杆/衍生品权限、审批规则、复审频率。
- **完成定义**：所有仓位/风险/卖出/再平衡建议都引用**同一套约束**；skill 中不再硬编码"前十大/现金比例"等阈值；基准用可投资总回报口径。
- 影响 ★★★★★　工作量 小–中　依赖 无

### P0-2 统一标的主数据 + 交易账本 + 组合主账
- security master（内部 ID、各市场代码、交易所、币种、行业、上市/退市）。
- transaction ledger（买卖、股息、费用、税、申赎、换汇、拆股、公司行动）。
- 从交易记录重建每日现金/持仓/成本/净值；统一 benchmark、FX、公司行动接口。
- **完成定义**：给定任意历史日期可重建当日持仓/现金/净值；与人工样例完全一致；风险/业绩/归因/告警/税务**只读这一个事实源**。
- 影响 ★★★★★　工作量 大　依赖 P0-1

### P0-3 统一数据层 v1（含 point-in-time）
- A/H/美统一行情、**前复权总回报**、财报、估值、FX、基准、公司行动。
- 每条记录含 `as_of`/`available_at`/来源/抓取时间/币种/单位/版本。
- **point-in-time 基本面**：回测不得使用当时尚未公布的数据（防前视偏差）。
- 数据新鲜度/完整性/跨源差异/缺失/异常值检查；记录供应商许可与抓取限制。
- **完成定义**：同一输入快照→相同输出；缺失/过期/冲突数据不被静默使用；保留原始值与标准化值可追溯。
- 影响 ★★★★★　工作量 大　依赖 P0-2

### P0-4 测试、数据治理与模型治理
- 核心工具加单元/边界/golden fixture 测试；skill 加固定样本输出回归测试。
- 模型登记：版本/用途/输入/限制/审批人/最近验证日期；异常处理/回滚/人工接管。
- **✅ 已修复的具体 bug（commit c05cc0e）**：`financial_rigor.py` 的 `calc --expr` 路径原先**先用 Python 浮点求值再转 Decimal**——`calc --expr "0.1 + 0.2"` 曾输出"精确值 0.30000000000000004"，与工具"无浮点漂移"承诺相悖。已改用 `ast.parse` + 递归 Decimal 求值器（全程 28 位精度），并以 AST 节点白名单堵死 eval 注入；现输出精确值 0.3。（`verify-market-cap`/`verify-valuation` 一直用 `exact()` 包裹输入，未受此 bug 影响。）**仍待补的是自动回归测试**——把 `0.1+0.2` 等作为 golden case 固化，这属于本节的测试基建 TODO。
- **完成定义**：`0.1+0.2` 等精确运算测试通过、不再输出伪精确；任一升级能识别是否破坏历史样例；仓位/买卖/风险建议须显示模型版本+关键假设+人工审批状态。
- 影响 ★★★★★　工作量 中　依赖 与 P0-2/3 并行

### P0-5 组合风险与业绩计算 MVP
- `tools/portfolio_risk.py`：波动、最大回撤、beta、HHI、行业/地域/货币暴露、相关性矩阵、历史压力情景。
- `tools/performance.py`：TWR、MWR、总回报、基准超额、费前/费后、多币种换算。
- 首批压力：市场下跌、利率、汇率、行业冲击、单一持仓归零。
- **完成定义**：组合与基准用一致的区间/频率/币种/总回报口径；与人工样例及第二实现交叉验证；**VaR 只作补充，不替代回撤/流动性/集中度/尾部情景**。
- 影响 ★★★★★　工作量 中–大　依赖 P0-1/2/3

## 五、P1 —— 跑通"研究—决策—组合—监控—复盘"闭环

### P1-1 结构化决策日志 + 投委会记录　`/decision-journal`
- 每次决策记录：论文版本、价格、估值区间、概率与情景、关键证伪条件、建议仓位、替代机会、审批、下次复审日。
- **区分"信息判断对但结果不利"与"推理/执行错误"**。
- 完成定义：历史时点只能看到当时已知信息，结果不得回填改写原判断。

### P1-2 估值模型框架（不止一个 DCF 公式）　`tools/dcf.py`
- 多阶段 DCF、反向 DCF、终值与 WACC 敏感性；SOTP（分部+投资资产+净现金-少数股东，查重复加计）。
- 行业模板：金融/资源/周期/SaaS 平台/消费/未盈利成长。每个假设记来源/日期/版本/敏感度。
- 完成定义：同输入可复现；单位/币种/股本口径有测试；终值占比过高自动警示；≥1 种独立方法交叉验证。

### P1-3 完整风险与压力测试
- 补因子/风格/流动性/容量/拥挤度/杠杆/对手方暴露；支持历史情景、假设情景、**反向压力测试**。
- 风险限额来自 IPS，越限生成解释+审批记录。

### P1-4 业绩归因与决策校准　`/performance-attribution`
- Brinson/因子/交易级归因（区分配置/选股/择时/汇率/费用/交互）。
- **决策校准**：概率预测的 Brier score、估值区间覆盖率、论文红线命中率 → 形成**可检索的错误模式库**（不是简单错题集）。
- ⚠️ 依赖账本/现金流/基准/费用/FX/公司行动，**工作量按"大"估**（不是单个中等 skill）。

### P1-5 统一 Watchlist + 论文库 + 自动监控
- 合并 watchlist.json、瓶颈 watchlist、召回池、持仓跟踪为一个入口。
- 状态机：发现→初筛→深研→候选→持有→退出→归档；每标的有负责人/论文版本/下一催化剂/红线/复审日。
- 自动维护财报/分红/监管/催化剂/论文 KPI 日历；告警有去重/优先级/重试/静默期/数据过期提示。

### P1-6 仓位与卖出纪律
- `tools/position_sizing.py`：分数凯利**仅作参考**，叠加 IPS 上限、流动性、相关性、组合风险预算、概率置信区间；**禁止仅凭"高赔率/单一评分"直接生成固定仓位**。
- `/sell-discipline`：论文证伪、估值透支、机会成本、风险越限、税务与流动性规则。
- **卖出属于决策与风险闭环，不归为 Alpha 来源。**

### P1-7 会计异常与治理筛查　`/forensic-accounting`、`/governance-screen`
- 应收/存货/现金流与利润背离/资本化/关联交易/商誉/审计意见/股权质押。
- Benford、Beneish M-Score **仅标记异常线索，不输出"证明造假"的结论**。
- 治理：股权结构、AB 股、薪酬对齐、减持、利益冲突。

## 六、P2 —— Alpha 实验室（在底座之上扩展策略）

> Alpha 模块必须明确策略假设、适用市场、风险预算、退出条件，并通过**点时、样本外、含成本**验证，不能靠事后案例证明有效。

### P2-1 新兴赢家发现引擎　`/emerging-winners`
> 用"新兴赢家"替代"十倍股猎手"——避免用结果标签驱动研究。**十倍是可能的结果，不是筛选条件。**

**候选维度（DNA 清单）：**
1. 市值与流动性允许较长成长空间——但**不把小市值本身当优势**。
2. TAM、渗透率、产业生命周期处于有利阶段（S 曲线早期）。
3. 单位经济成立，增长可复制、有再投资空间。
4. 收入/毛利/现金流/资本效率**相互验证**（不是单点故事）。
5. 创始人/管理层资本配置有**可核实**记录。
6. 存在被市场忽略的业务期权或认知差。
7. 有明确竞争壁垒，而非只是热门主题。
8. 估值**允许失败**——不靠"永久高估值"来实现戴维斯双击。

**组合方法（关键）：** 只作为**有明确风险预算的卫星策略**——先定死最大总仓位/单一仓位/流动性/最大损失，再选候选。用塔勒布杠铃：一篮子小仓位押多个非对称候选，允许多数失败、靠少数拉动整体。**KPI 是提高组合期望收益，不是"找到几只十倍股"。**

**验证要求：** 用当时可得的股票池与财务数据；纳入退市/失败样本与交易成本；报告命中率、假阳性、最大回撤、资金容量、样本外表现。

### P2-2 多因子与系统化筛选　`/factor-screen`
- 价值/质量/成长/动量/低波/规模/盈利修正因子；行业/市场中性化 + 因子相关性。
- 点时成分股、退市收益、再平衡、换手、滑点、税费；训练/验证/样本外严格分离。
- **因子用于缩小研究范围，不做黑箱自动下单。**

### P2-3 宏观 regime 与资产配置（策略可选）　`/macro-regime`、`/asset-allocation`
- 增长/通胀/流动性/信用/利率/汇率/政策周期；目标区间、再平衡触发、风险预算、基准。
- 明确宏观判断只影响哪些决策，**避免在自下而上研究里随意改估值假设**。

### P2-4 行业景气、轮动与主题（策略可选）　`/sector-rotation`、`/thematic`
- 订单/价格/产能/库存/盈利修正/资金流/相对强弱；主题定义、受益纯度、拥挤度、估值、退出条件。
- 与 industry-research/funnel 共享行业分类与候选主数据。

### P2-5 事件驱动与特殊机会　`/special-situations`
- 并购/分拆/私有化/要约/回购/重组/指数调整/融资事件；每类单独建模成交概率、时间价值、法律条件、融资风险、下行情景。
- **不用"确定性较高"概括整类**；特殊机会只是"收益驱动与市场 beta 可能不同"。

### P2-6 一手验证与信息 Edge　`/scuttlebutt`、`/channel-check`
- 客户/供应商/渠道/专家访谈前，先过 MNPI/保密/隐私/利益冲突/记录政策检查（见控制线）。
- 区分**可验证事实 / 受访者观点 / 研究员推断**；另类数据记授权/代表性/更新频率/失效风险。

### P2-7 分市场与另类资产
- A 股：制度、涨跌停、北交所、可转债条款、股权质押、治理。
- 港股：流动性、配售、**老千股特征（防雷）**、AH 溢价、港股通资金。
- 美股：做空、期权、回购、13F、SPAC、证券诉讼。
- 一级/REITs/债/商品/加密：分别建立 mandate 后再开发。
- ⚠️ "可转债下有保底""小盘更容易十倍"等**只能作待验证假设**，须同时评估信用/赎回/稀释/流动性/极端损失。

## 七、🆕 AI 系统特有治理（本系统的差异化控制线）

**这是一个 AI 驱动的投资系统——它有人类机构没有的失效面，必须专门治理。** 项目现有加固（联网预检、report_audit 准出、financial_rigor、"联网失败禁止伪装"、"客观/正反两面"原则）正是 AI 治理的雏形，应成体系升级到 L4。

| AI 特有风险 | 表现 | 治理动作 |
|---|---|---|
| **幻觉/编造** | LLM 编造数据、来源、财务数字 | 关键数据双源交叉（已有 financial-data）+ report_audit 准出（已有）→ 扩展到每份报告强制抽检、来源可点击可核 |
| **断网伪装** | 联网失败却用训练知识冒充实时结果（本系统最危险失效，见 issue #58） | 已有 WebSearch 预检 + "联网失败禁止伪装"→ 升级为**硬门禁**：检测不到联网证据即拒绝出研究结论 |
| **过度依赖 LLM 判断** | 把"AI 说好公司"当成结论 | 强制分离**"AI 说了什么" vs "数据证明了什么"**；大师镜片/评分只作思维工具，最终判断落到可核事实 |
| **prompt/skill 版本漂移** | skill 改一版，输出静默变化，无法复现历史结论 | skill 纳入模型登记（版本/变更记录）+ 固定样本回归测试（P0-4）；报告标注生成时的 skill 版本 |
| **不可复现** | 同一问题两次跑结果不同 | 关键量化走确定性工具（financial_rigor/dcf/portfolio_risk），LLM 只做解释与判断；数值结论可被工具重放 |
| **知识截止误用** | 用训练截止日的旧事实当"最新" | 强制 `date` 校准 + 报告头标注数据截止日（已有规范）→ 纳入自动检查 |
| **谄媚/确认偏误** | 迎合用户预设立场 | 已有"不预设立场/正反两面/反共识"原则 → master-lens 异见庭强制引入唱反调视角，并纳入决策日志 |

> **完成定义**：任何一份 AI 产出的研究/决策，都能回答"这段结论是联网核实的事实、还是模型推断？用的哪个 skill 版本、哪个数据快照？"——达不到就降级标注，不伪装确定性。

## 八、🆕 投研运营节奏（机构的心跳）

能力要靠**固定节奏**才能持续运转，否则再多 skill 也是一次性动作。

| 周期 | 动作 | 依赖能力 |
|---|---|---|
| **每日** | 盘前：持仓/watchlist 重大新闻扫描、红线触发检查、异动归因（news-pulse） | 自动监控、告警 |
| **每周** | 持仓健康度巡检（thesis-tracker）、新增候选初筛、数据管线新鲜度检查 | watchlist 状态机、数据治理 |
| **财报季** | 逐个持仓财报精读（earnings-review/team）、论文 KPI 更新、估值刷新 | 决策日志、估值框架 |
| **每季** | **组合层复盘**：业绩归因 + 决策校准（Brier score）+ 风险预算利用 + 淘汰无效规则 | 归因、风险、KPI |
| **每年** | IPS 复审（基准/风险预算/禁投是否仍合理）、能力成熟度重评、错误模式库总结 | IPS、成熟度盘点 |

> 没有节奏，"能力"只是躺在仓库里的 skill；有节奏，它才是一个运转的机构。

## 九、🆕 反模式清单（这类系统最常见的死法）

| 反模式 | 表现 | 对策 |
|---|---|---|
| **过拟合/数据窥探** | 回测调参调到漂亮，实盘失效 | 训练/验证/样本外分离；样本外+含成本验证（P2 门槛） |
| **虚假精确** | 把估计值报成小数点后两位的"精确" | 会失败原则：数据不足即停/降级；区分事实与估计 |
| **告警疲劳** | 告警太多→全部忽略 | 告警去重/优先级/静默期（P1-5） |
| **论文漂移（thesis creep）** | 事实变了却悄悄改说辞不认错 | 决策日志不可回填（P1-1）；thesis-drift 检测措辞漂移 |
| **抱团/伪分散** | 名义分散实则押同一宏观/因子 | 组合相关性与因子暴露（P0-5/P1-3） |
| **叙事拟合** | 先有结论再找数据 | 客观原则 + 异见庭（master-lens）+ 空方论点强制 |
| **幸存者偏差** | 只看活下来的赢家 | 回测纳入退市/失败样本（数据治理控制线） |
| **重买入轻卖出** | 有买入框架无退出纪律 | sell-discipline（P1-6） |

## 十、Definition of Done（每个 skill/工具的落地标准）

同时满足才算"机构能力已落地"：

- [ ] **范围明确**：解决/不解决什么、适用什么 mandate
- [ ] **输入明确**：字段/单位/币种/时点/来源/缺失值规则
- [ ] **输出明确**：结论/置信度/假设/限制/人工审批点
- [ ] **可复现**：同一数据快照+配置+版本→相同结果
- [ ] **可测试**：正常/边界/异常/历史 golden case 均有自动测试
- [ ] **防偏差**：point-in-time、幸存者、前视、成本、退市样本
- [ ] **可追溯**：结论→来源→转换→模型版本→决策人
- [ ] **会失败**：数据不足即停/降级，不制造精确幻觉
- [ ] **可监控**：成功率/耗时/数据新鲜度/异常/人工覆盖率
- [ ] **可复盘**：上线前定效果指标，上线后定期校准、淘汰无效规则

## 十二、依赖关系与里程碑

```
投资授权/IPS
    ↓
标的主数据 + 交易/现金账本
    ↓
点时数据层 + 数据质量
    ↓
业绩基线 ─→ 组合风险 ─→ 压力测试
    │              │
    └→ 决策日志 ─→ 归因/校准 ─→ 规则迭代
                   │
统一 Watchlist/监控 ┘

测试、模型治理、合规、AI 治理、审计留痕：贯穿全部阶段
```

| 里程碑 | 目标 | 核心交付 | 退出条件 |
|---|---|---|---|
| M0 定规则 | 明确服务什么策略 | IPS、基准、风险预算、审批与数据边界 | 任一建议能判断是否符合 mandate |
| M1 建事实源 | 历史投资可完整重建 | security master、交易/现金账本、点时数据 v1 | 任意日期持仓与净值可重放 |
| M2 闭环 MVP | 能衡量风险与结果 | 业绩、风险、决策日志、论文版本 | 一笔投资可从决策追踪到结果 |
| M3 可持续运行 | 能自动监控与复盘 | 统一 watchlist、日历、告警、归因、校准 | 告警与复盘有稳定运行记录 |
| M4 扩展 Alpha | 系统发现并验证新机会 | emerging-winners、factor、macro/sector | 通过样本外与含成本验证 |
| M5 真实资管运营 | 支持第三方资产 | 交易、托管、NAV、合规、客户报告 | 按属地要求完成独立评估 |

### 对"直觉排序"的关键修正
| 直觉 | 修正后 |
|---|---|

## 十三、最终判断

AI Berkshire 已形成一套覆盖面广、可重复运行的**公司研究工作流**，也有行业漏斗、瓶颈发现、动量筛选、召回池等机会发现原型。它现在最需要的不是继续横向增加"大师"和主题 skill，而是完成三次升级：

1. **从报告升级为记录系统**——统一标的/交易/持仓/论文/决策的事实源。
2. **从能运行升级为可信赖**——点时数据、测试、模型治理、AI 治理、审计留痕。
3. **从研究个股升级为管理闭环**——能算组合风险与业绩、能监控论文、能归因和校准。

完成底座后，"新兴赢家""宏观 regime""板块轮动""特殊机会"这些 Alpha 模块才有可靠的输入、风险边界和评价标准。

> **它现在擅长"确认一家好公司值不值得买"；下一步要让它对每一个数据、判断、仓位、结果都能回答——依据是什么、当时知道什么、承担多少风险、最终哪里对了/错了。** 前者是不亏钱的研究能力，后者才是一个可信赖、可进化的投资机构。
