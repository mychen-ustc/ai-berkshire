## 三、仍缺什么（诚实盘点）

系统已过"缺工具"阶段。真正的短板集中在**运营化(L4→L5)**、**研究闭环**、**代码质量治理**三处：

1. **无运营监控**：64 工具 + cron 会跑，但**没有健康检查**——数据源挂了、cron 静默失败、数据变陈旧，没人知道。这是距"运转的机构"最大的缺口。
2. **代码质量无门禁**：本轮 **两次因变量遮蔽(horizon、market)导致复盘崩溃**——单元测试(测纯函数)测不到这类集成层 bug。缺一个**静态检查门禁**(遮蔽/未定义/未用)兜底。
3. **因子风险未分解**：factor_library 给了**暴露**,但没做**因子协方差→组合风险分解**(X%风险来自动量、Y%特异)——旗舰因子能力的最后一块。
4. **T1 线索无自动分诊**：pipeline 的 T1 候选池现有 24 个线索,但晋级 T2 靠手工;缺**快速筛(估值/质量/forensic)自动排序**,闭合"线索→研究"环。
5. **点时数据覆盖浅**：pit_financials 仅 ~6 只美股;要让 backtest_rigorous/因子质量维度**广泛**可用,需扩覆盖。
6. **三表模型(T3-4)**、**ESG/另类(T3-5)**、**P5 资管运营**：更后/条件性。

## 四、下一批方向（4 选，按性价比 + 呼应本轮教训）

### 方向 A · 运营监控与健康检查（L4→L5）影响★★★★★
cron 失败告警 + 数据源新鲜度/连通性检查 + dead-man's-switch + 运行健康看板。让系统"出问题会喊你"，从"会跑的脚本"变"可信赖的机器"。**最大运营缺口、长期最该补。**

### 方向 B · 代码质量硬门禁（防本轮反复踩的坑）影响★★★★☆
零依赖 AST 静态检查:循环变量遮蔽外层名、未定义名、未用导入等——正是两次让复盘崩溃的 bug 类。与 report_audit(报告门禁)对称,做**代码门禁**,纳入提交前检查。**ROI 高、直接止血。**

### 方向 C · 因子风险分解（完成旗舰因子能力）影响★★★★☆
factor_library 加**因子协方差 + 组合风险归因**:把组合波动分解为各命名因子贡献 + 特异风险。回答"我的风险到底来自哪个因子"。**研究力立竿见影。**

### 方向 D · T1 线索自动分诊（闭合流水线闭环）影响★★★★☆
对 pipeline T1 候选池(现24线索)自动跑快速筛(估值/质量/forensic/相关性),按"是否值得晋级T2"排序打分。让"发现线索→纳入观察"从手工变半自动。**刚建的流水线的自然延伸。**
